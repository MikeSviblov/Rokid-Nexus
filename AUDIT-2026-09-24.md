# Первичный аудит безопасности Rokid Nexus — 24 сентября 2026

## Итог

1. **Текущий код не рекомендую ставить с self-arm на очки с личными заметками до исправления H1.** Входящий Bluetooth SPP не аутентифицирует телефон, но получает доступ к доверенным управляющим маршрутам, включая создание pairing-кода ADB.
2. Собственная подпись APK полезна для контроля обновлений, но **не исправляет доверие транспортного канала** и не ограничивает уже выданные полномочия shell.
3. Для рабочего использования также нужны закрепление подписи APK очков, отключение внешних установщиков и возможность полного добровольного disarm; приоритеты и места правок приведены ниже.
4. Массового чтения и отправки текста всех приложений в рассмотренном коде не обнаружено. Однако Accessibility имеет глобальный доступ, а аппаратные keycode записываются в logcat вне собственного редактируемого Surface Nexus.
5. Wireless ADB реализован фиксированными командами для API 32; универсального plugin API «выполни shell» не найдено. Получение pairing-кода всё равно позволяет доверенному компьютеру получить обычный `adb shell` в рамках возможностей прошивки.
6. Nexus Store проверяет SHA-256 и подпись плагина по удалённому каталогу; установщик glasses-hub не проверяет подписанта самостоятельно. Автоматические проверки обновлений есть; автоматической фоновой установки всех обновлений не обнаружено.
7. Минимальный целевой набор — два release-хаба и Wireless ADB, собранные своим ключом, без остальных плагинов, облачной речи и внешнего Store. Это уменьшает поверхность, но требует устранить H1, а не только сократить набор APK.
8. Это статический аудит исходников, **не подтверждение безопасности прошивки, vendor SDK или готовых APK**. Эксплуатация на устройствах, сетевой захват, сборки и тесты не выполнялись.

**Последствие.** Подключившийся к этому RFCOMM-сервису посторонний peer получает управляющий канал без Nexus-grant. Условная цепочка: Bluetooth-доступ → запрос pairing → получение кода → доступность ADB очков по Wi-Fi → спаривание своего компьютера и shell. Нужны подходящее состояние self-arm/API 32, доступная сеть и фактическая возможность соединения на прошивке. Цепочка **не испытана**; это не утверждение об интернет-RCE или root. Также возможны управление UI и перехват/нарушение ответов без стадии ADB.

Важно: insecure RFCOMM **не означает обязательно незашифрованный радиоканал**. Android указывает, что на Bluetooth 2.1+ шифрование есть, но ключ не аутентифицирован и защита от MITM отсутствует: [BluetoothAdapter API](https://developer.android.com/reference/android/bluetooth/BluetoothAdapter#listenUsingInsecureRfcommWithServiceRecord(java.lang.String,%20java.util.UUID)).

**Правка.** Ввести взаимную аутентификацию Nexus peer, привязку к явно подтверждённому устройству и защиту каждого управляющего сеанса от replay; ответы привязать к той же сессии. Secure RFCOMM и проверка enrolled/bonded peer полезны как дополнительный слой. Одного публичного UUID, адреса Bluetooth либо поля `pluginId` недостаточно. До исправления не считать защищёнными никакие hub-only маршруты на удалённом входе.

### H2 — HIGH: установщик glasses-hub не закрепляет подписанта APK

**Доказательства.** Телефон получает release, скачивает APK, проверяет digest **только если он присутствует**, разбирает package name и передаёт файл в CXR `appUploadAndInstall`: [BusHubService.kt:3950](/home/mike/projects/rokid-nexus/phone-hub/src/main/java/com/anezium/rokidbus/phone/BusHubService.kt:3950), [BusHubService.kt:3981](/home/mike/projects/rokid-nexus/phone-hub/src/main/java/com/anezium/rokidbus/phone/BusHubService.kt:3981), [BusHubService.kt:4027](/home/mike/projects/rokid-nexus/phone-hub/src/main/java/com/anezium/rokidbus/phone/BusHubService.kt:4027). **Последствие.** Первая установка/повторная установка доверяет содержимому GitHub release. Подменив источник, можно подать иной APK с тем же package name; SHA из того же скомпрометированного источника не удостоверяет издателя. Это особенно существенно для приложения, которому затем выдают Accessibility и shell. Обычная проверка Android при обновлении уже установленного пакета сохраняет защиту от несовместимой подписи; обход этой защиты здесь **не показан**. См. [Android app signing](https://developer.android.com/studio/publish/app-signing).

**Правка.** Для своего форка закрепить SHA-256 сертификата glasses-hub независимо от сетевого metadata, проверять package/version и обязательный digest, отказать при невозможности разобрать APK. До этого исключить удалённую установку очкового APK и использовать заранее проверенный собственный артефакт.
